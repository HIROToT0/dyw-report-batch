# 检测报告批量编制技能（混凝土试块抗压 · 模板 551）

把一份 Excel 台账变成一整批**已编制、已生成、已上传**的检测报告，并支持批量
**下载原始记录 PDF → 合并成带书签的一册**。

一套走通的实战流程，不是拼凑的脚本：预检 → 演练核对 → 批量执行 → 验收 → 下载合并。

## 能做什么

| 环节 | 说明 |
|---|---|
| 台账驱动 | 按 Excel（`任务列表` sheet）里的报告编号逐份处理，多组样品自动识别 |
| 字段补齐 | 自动补齐报告渲染字段（工程名称/见证单位/见证人/砼厂家/工程部位/龄期/试验仪器） |
| 检测数据 | 按模板公式复刻长/宽/极限荷载及派生值，逐行"添加"到系统 |
| 备注与温湿度 | 备注A 按规则拼装（含同条件养护的累计温度），温湿度取台账列 |
| 上传 | 保存 → 生成 → 轮询文件产出 → 上传，全流程一次跑完 |
| 验收 | 一份 CSV 核对 downloadFlag / 渲染字段 / 备注A / 检测行数 / **组号顺序** |
| 下载 | 批量下载原始记录或电子报告（PDF / Word） |
| 合并 | `merge_pdfs.py` 按台账顺序合并，加书签，列出多页文件 |

## 快速开始

```bash
# 依赖
pip install requests openpyxl pypdf

# 站点地址与凭证（技能内不内置任何地址和密码）
export DYW_BASE=http://<你的站点>/Report
export DYW_USER=<你的账号>
export DYW_PWD=<你的密码>

export DYW_LEDGER="C:/path/未发报告.xlsx"      # 台账

S=path/to/scripts

python $S/precheck.py                          # 1. 只读预检，不写任何数据
python $S/run.py drill <报告编号>                # 2. 单份演练（不上传）
python $S/run.py fetch <报告编号>                # 3. 下载报告核对字段
python $S/fix_and_run.py                        # 4. 全量编制上传
python $S/final_check.py                        # 5. 验收

python $S/download_records.py --kind record --type pdf --out outputs/本次
python $S/merge_pdfs.py --ledger "$DYW_LEDGER" \
    --folder outputs/本次/原始记录_pdf --out outputs/原始记录_合并.pdf
```

凭证也可以放在 `~/.workbuddy/dyw_credentials_{prod|test}.json`（`{"user":"...","pwd":"..."}`），
按 URL 是否含 `test.` 自动选择文件。**技能目录里不含任何密码。**

## 台账格式

`sheet 名 = 任务列表`，列位置**按表头名**识别（列序会变，不要依赖列号）：

| 表头 | 内容 |
|---|---|
| 报告编号 | 完整编号，如 `DWYHY20260000009050`（只填后 5 位查不到） |
| 样品编号 | `报告编号-N`，N 为组号；多组占多行 |
| 温度 | 22 / 23.5 → 写 1 位小数 |
| 湿度 | 68 / 70 → 写整数字符串 |
| 进度 | 脚本回写：已完成 / 已生成(未上传) / 失败:原因（无此列则追加到末列） |

## 三个最容易踩的坑（都已在脚本里处理）

1. **必须逐行"添加"检测数据**，不能只在保存时提交列表。
   只提交的话数据能读回、保存也返回成功，但服务端**不产出报告文件**，
   上传必然报 `未获取到报告文件信息！`——典型的"假成功"。

2. **必须补齐渲染字段**。模板把业务字段分成两组，报告 Word/PDF 渲染用的是
   第二组（可填写组）。只填第一组，报告里这些栏位全是空白。

3. **10 组及以上必须按组号数值排序**。Excel 导出时把组号当字符串排，
   10 组会变成 `1,10,2,3,4...9`；服务端按添加顺序生成表格行，
   不重排报告里显示顺序就是乱的。`final_check.py` 有 `组号顺序` 列专门核对这一点。

更多坑（接口编码方式、字段映射、常见报错对照）见 **[SKILL.md](SKILL.md)**。

## 实测参考

一批 129 份 / 171 行（含 1 份 10 组）的台账：

| 步骤 | 耗时 | 结果 |
|---|---|---|
| 预检 | 21s | 129/129 通过 |
| 演练 + 核对 | 4s | 字段齐全 |
| 全量 | 551s | 上传成功 129/129 |
| 验收 | 60s | downloadFlag=1 全中，组号顺序全对 |
| 下载原始记录 | 20s | 129/129 |
| 合并 PDF | 3s | 129 份 / 133 页 |

## 状态字段的坑

系统里的 `reportStatus` **不能当成败判据**：只要没走完审批流程，
界面一律显示"报告待编制"。判断成败唯一硬指标是 `downloadFlag == "1"`
加上报告文件能下载、内容字段齐全。
